# Work DevTools v1.0.3

发布日期:2026-08-11

`1.0.3` 为常用开发地址的页面补充可选 Wiki 字段,新增「图片压缩」一级工具(本地 WASM + TinyPNG 云压缩双引擎,多 Key 轮换与额度展示),新增「查看配置」入口与「导出敏感信息」独立开关,并优化版本更新检查为每次打开管理页即查(ETag 不消耗 GitHub 限流配额)。

## 新增功能

### 常用开发地址

- 常用开发地址的页面新增可选「Wiki 地址」输入框,保存时按完整 HTTP/HTTPS 地址规范化,留空时不落库。
- 页面行新增「Wiki」按钮,仅在已填写 Wiki 地址时显示,点击在新标签页打开;未填写时不占用行内空间。
- Wiki 按钮使用 Amber 业务色,与项目级 Wiki 入口保持一致的视觉语义。

### 图片压缩

- 新增「图片压缩」一级工具,包含「压缩工具」和「压缩设置」两个 Tab,可通过侧栏或扩展图标右键菜单进入。
- 压缩工具支持拖拽或点击批量添加 PNG / JPEG / WebP 图片,按队列展示文件名、原始大小、压缩后大小和压缩率,可单张下载或勾选后打包为 zip 下载。
- 本地引擎基于 `@jsquash/*` 系列 WASM 编解码器:PNG 走 oxipng 无损优化(可调级别 0-6),JPEG 走 MozJPEG(可调质量),WebP 走 libwebp(可调质量),其它格式回退到 Canvas API;支持最长边像素限制。
- TinyPNG 云引擎支持配置多把 API Key:遇到 429(配额耗尽)或 401(无效)时自动切换下一把 Key,全部不可用时聚合失败原因给出可读错误。
- 设置页支持多 Key 列表增删,每行带显示/隐藏切换;压缩时展示每把 Key 的剩余配额(从响应 `Compression-Count` header 读取,持久化到 `tinifyKeyUsage`,按 Key 索引对齐展示为「N/500」)。
- 引擎选择写入持久设置,压缩时与设置页同步;未配置 Key 选择 TinyPNG 时给出引导提示。
- 压缩设置页提供引擎分段单选、本地参数表单、TinyPNG API Key 列表,并明确告知 Key 与配额信息。

### 配置与备份

- 左侧导航「版本与更新」区下方新增「查看配置」入口,点击弹框展示当前完整工作台 JSON(等宽字体,带一键复制与蒙层关闭)。
- 「备份与同步」页新增独立「导出敏感信息」开关(默认关闭,位于 Tab 导航与内容之间):开启后 JSON 导出和 WebDAV 推送会携带 TinyPNG API Key 列表,迁移到其他设备后免重复配置;关闭时只包含普通工具数据。

### 版本更新检查

- 打开管理页即触发版本检查,不再限制为每 24 小时一次。
- 通过 `ETag/If-None-Match` 与 GitHub 协商:大多数请求返回 304,不计入未认证 60 次/小时的限流配额,只有新 Release 发布后的第一次请求返回 200 计 1 次,实际配额消耗接近零。
- 网络失败/限流时不写入新 `checkedAt`,下次打开管理页可立即重试;同时保留上次缓存的更新提示,不会因网络问题清空已展示的「有新版本」状态。

## 调整内容

### 常用开发地址

- 页面保存逻辑复用项目级 `normalizeDevWikiUrl`,统一对空值、协议和格式进行校验,错误提示与项目 Wiki 保持一致。
- 页面编辑弹框在 path 字段下方追加 Wiki 输入框,说明文案明确「填写后列表行会出现 Wiki 按钮」。
- 页面数据结构和规范化函数同步支持 `wikiUrl` 可选字段,旧数据缺少该字段时按未设置处理,保持兼容。

### 图片压缩

- 根数据版本升级到 3,新增 `tools.imageCompressor`;旧数据缺少该字段时自动补为默认设置,Cookie Injector 与常用开发地址数据保持不变。
- `MANAGER_NAV` 新增 `image-compressor:compress` 和 `image-compressor:settings` 两个深链。
- Manifest 新增 `web_accessible_resources`(仅 wasm 资源)和 `content_security_policy.extension_pages`,允许 `'wasm-unsafe-eval'` 与 TinyPNG API 域名 `connect-src`;Vite `optimizeDeps.exclude` 排除 `@jsquash/*` 以避免预构建干扰 WASM 加载。
- TinyPNG API Key 列表直接存于 `tools.imageCompressor.settings.tinifyApiKeys`,与本地引擎参数并列,本机持久化即数据本身;旧版本独立键中的单把 Key 在打开设置页时自动迁移到数组。
- 导入 JSON 或 WebDAV 拉取时按「导出敏感信息」开关决定是否携带 Key 列表;关闭开关时导出/推送会从克隆数据中 `strip` 掉 `tinifyApiKeys` 字段,本地数据不受影响。
- 管理页和扩展描述同步提到图片压缩能力。
- 导入导出与 WebDAV 同步路径统一对 `tools.imageCompressor` 做规范化,缺失或结构不全时使用默认设置。
- 压缩页面提示条、拖入区与队列卡片之间补 8px 间距,符合 UI 规范。
- UI 沿用工作台规范:Sky 用于本地引擎选中态、Violet 用于 TinyPNG 语义、Amber 提示需上传第三方;压缩列表复用 `divide-y` 行样式和虚线空状态。
- TinyPNG 端点优先 `api.tinify.com`,失败时回退 `api.tinify.cn`,兼顾国内访问稳定性。

### 版本更新检查

- `RELEASE_CHECK_INTERVAL_MS` 改为 `0`,缓存仅用于打开瞬间的初始展示与携带 ETag。
- 缓存结构新增 `etag` 字段,304 时从响应 header 同步更新 etag、更新 `checkedAt`,保留旧 `latestVersion`/`releaseUrl`。
- 200 时正常解析 + 读取新 etag,完整更新缓存。
- 失败路径不再写入 `checkedAt = now`,避免 24 小时内被锁住无法重试的问题。

## 升级注意事项

- 更新后自动补全空的图片压缩设置,无需手动迁移。
- 本地压缩依赖 WASM;首次使用时浏览器会从扩展包内按需加载 wasm 资源,无需联网。
- 如需使用 TinyPNG 云压缩,请到「图片压缩 → 压缩设置」添加 API Key;每把 Key 独立配额 500 次/月,超出后引擎自动切换下一把。
- 已配置过旧版本单把 Key 的用户,首次打开设置页会自动迁移到新数组,无需重新输入。
- 更新扩展后重新打开管理页,编辑任意页面即可看到新增的「Wiki 地址(可选)」输入框。

## 安装方法

1. 从 GitHub Releases 下载 `work-devtools-1.0.3-chrome.zip`。
2. 解压 ZIP 文件。
3. 打开 Chrome 扩展管理页并开启开发者模式。
4. 点击「加载已解压的扩展程序」,选择解压后的目录。
